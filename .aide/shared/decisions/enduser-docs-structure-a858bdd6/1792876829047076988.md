# enduser-docs-structure

**Decision:** Organise user documentation by reader intent (Diátaxis: tutorial, how-to, reference, explanation), not by code structure

## Rationale

Users arrive with a question, not a file path. A structure that maps to why someone is reading (learning, doing, looking up, understanding) gets them to the answer faster than one that mirrors the engineering team's module boundaries.

## Details

Tutorials walk a beginner through a first successful outcome. How-to guides solve specific tasks for users who already know the basics. Reference is dense, complete, and looked-up not read. Explanation covers background, trade-offs, and why the product is the way it is. Keep each section focused on its quadrant; mixing them is the most common cause of docs that feel bloated yet incomplete.
