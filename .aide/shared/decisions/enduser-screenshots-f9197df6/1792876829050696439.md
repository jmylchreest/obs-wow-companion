# enduser-screenshots

**Decision:** If the product has a visual surface, screenshots or short recordings live in the repo next to the docs that reference them

## Rationale

External-hosted images rot, get re-encoded, or 403 without warning. Committed media stays in sync with the docs it illustrates and moves with the project under version control.

## Details

Commit optimised images (PNG / WebP / AVIF) or short recordings (MP4 / WebM / animated SVG) next to the Markdown that references them. Automated capture (Playwright screenshot tests, Percy / Chromatic visual regression, platform-native tools like xcrun or adb for mobile) is encouraged but not required — the rule is about where the media lives, not how it was produced. Prefer system-agnostic framing (avoid OS window chrome that dates quickly) and annotate with descriptive alt text for accessibility and search.
