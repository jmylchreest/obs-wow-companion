# companion-crash-activity-recovery

**Decision:** Restore persisted automatic activity state and combat-log cursors after a crash. Replay missed events before inactivity or dungeon-exit expiry and before stopping recovered capture. Continue the same activity when still active; finish from logged completion, exit grace or inactivity rather than abandoning merely because Companion restarted. Recover OBS control only with the existing endpoint, output-path, duration, byte-counter and fresh-file checks; scene equality alone is insufficient. Orderly Quit still ends active capture.

## Rationale

A restart can occur mid-key or after completion. Preserving activity identity and waiting for log reconciliation avoids duplicate recordings, premature stops and orphaned owned capture.
