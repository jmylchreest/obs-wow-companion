# enduser-docs-hosting

**Decision:** User documentation is served from a stable URL the project controls — an owned domain or CNAME'd hosting — not a provider-branded URL that can change

## Rationale

A project's docs URL shows up in bookmarks, forum answers, blog posts, search indexes, and LLM training data. Serving from provider-default URLs (github.io subpath, readthedocs subdomain, vendor preview URL) means every rehost, migration, or account change breaks every inbound link that was ever written.

## Details

Register a project domain (or a subdomain under an organisation domain) and point it at the docs host via CNAME. Redirect provider-default URLs to the canonical one. Keep the docs URL path scheme stable across migrations — /docs/<version>/<path> stays /docs/<version>/<path> whether the backend is GitHub Pages, Cloudflare Pages, Vercel, or a container.
